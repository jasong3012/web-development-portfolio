// 03 agentic ai workflow

How I ship with AI agents.

I build with Claude Code and Claude Design using Anthropic's 4D AI Fluency Framework: Delegation, Description, Discernment and Diligence.

Claude does the legwork. I keep the judgment, the review and the accountability.

FIG 03 · the 4D framework, applied

4 competencies + toolset · how I work with Claude

The skill

Delegation: Thoughtfully deciding what work to do with AI vs. doing yourself.

How I apply it

Before each change I split the work: mechanical, well-defined tasks go to Claude Code, while anything that needs business context or taste stays with me.

Claude does
Scaffolding componentsCustom codeRefactorsCSS clean-upRepetitive QA checks
I own

Business goals, brand rules, conversion targets, UX decisions and the final call on what ships.

The skill

Description: Communicating clearly with AI systems.

How I apply it

I turn business goals, brand rules and conversion targets into a clear spec with acceptance criteria. A CLAUDE.md file in each repo gives Claude Code the standing rules: project structure, image formats, the checks to run and the Git workflow. I share reference designs, screenshots and existing content as context, and explore visual directions in Claude Design before they reach code.

Claude does
Reads the spec and CLAUDE.mdProposes a planAsks when a request is ambiguous
I own

The brief, the acceptance criteria and the project rules.

The skill

Discernment: Evaluating AI outputs and behavior with a critical eye.

How I apply it

Claude Code proposes a plan and I approve or redirect it before any code is written. Visual changes come back as desktop and mobile previews first. I review every diff and run accessibility, responsive, SEO and performance checks before anything merges.

Claude does
Plans before codeDesktop & mobile previewsAutomated browser checks
I own

Approving the plan, reviewing every diff and deciding what is good enough to ship.

The skill

Diligence: Ensuring you interact with AI responsibly.

How I apply it

I am accountable for every change that ships. Each one goes through its own pull request with a summary and how it was checked, so the full history is on GitHub. The agent may only state facts I have provided: no invented metrics, clients or testimonials. It never force-pushes to main or bypasses checks.

Building this portfolio with an AI agent, one pull request at a time

Nov 2026 · Jason Grant · Agentic workflow

This site was built by Claude Code working from my brief, a reference template and my old portfolio. I stayed in charge of direction and review. Here's how the loop worked, and the guardrails that made it safe to hand an agent the merge button.

The brief

I asked for a landing page that would show my web development work and my agentic, AI-assisted process to hiring managers and web tech leads. I gave the agent three inputs:

  • a full HTML template to use as a structural reference,
  • my previous portfolio site, as the source for content and project images,
  • a short list of skills, plus my contact email.

From template to page

The agent scraped my old project pages, copied the mockups into the repo and converted the large PNG collages to WebP, taking them from about 2 MB to about 0.2 MB each. It then wrote a single self-contained index.html: inline CSS and JS, no build step, and nothing to install.

Before anything was committed, it rendered the page in headless Chromium at desktop (1440px) and phone (390px) widths, checking for console errors and horizontal scrolling.

One rule I set early: no invented metrics, clients or testimonials. When the agent needed a number, it used only figures I'd provided, like 5+ years in WordPress and 2 years on HubSpot CMS.

The permissions wall

The first pushes to GitHub failed with a 403. The agent could read the repository but not write to it. Installing the Claude GitHub App on the repository fixed it. Until then, I uploaded a zip of the build through the GitHub web interface, so the work never stalled.

Automating the PR loop

Once access worked, I wanted every change to go through a pull request without me clicking through each one. The agent added a CLAUDE.md file to the repo, so every future session follows the same standing instruction:

FIG. 1 · CLAUDE.md, git workflowexcerpt
For every change Jason requests:
1. Start a branch from the latest origin/main.
2. Commit with a clear message and push the branch.
3. Open a pull request into main.
4. Merge the pull request immediately.
5. Reply with the pull request link and a summary.

If a merge is blocked (conflict, failing checks,
branch protection), stop and report it.

Fig. 1 — The guardrail that matters is the last line: the agent stops and reports a blocked merge instead of forcing it.

PRChange
#1First version of the landing page, built from the template and my old portfolio
#2CLAUDE.md with project notes and the auto-merge workflow
#3Restyle to a neon visual reference (Version A)
#4An editorial Version B, with home, approach and blog views
#5Approach content moved onto the homepage, under the gateway, for SEO

Iterating: an A/B experiment

With the loop in place, design iterations became cheap. Version A is a bold, neon landing page. Version B, the page you're reading, is a calm editorial layout: a minimal gateway that opens onto a long-form homepage, plus a blog. Both use the same content and images, so the comparison is about presentation alone.

Takeaways

  • Give the agent real inputs. A reference template and existing content produced far better results than a description would have.
  • Write the rules down. A CLAUDE.md in the repo means every session follows the same workflow and content rules.
  • Automate the loop, not the judgment. The agent branches, commits, opens and merges pull requests. I decide what gets built and review the result.
